# JantamaReviewer

雀魂の四人麻雀（半荘）を、AI（Mortal）の答えを見る前に自分の答えと理由を確定させてから検討するための、個人用の Windows アプリです。対局中は、小さなウィジェットで「迷った」瞬間と、局ごとの出来（〇△✕）を記録します。対局のあとは、mjai.ekyu.moe の検討結果を取り込み、記録と結びつけて見直します。見直しは、AI の答えを隠したまま自分の答えと理由を書く出題、間隔を空けた解き直し、半荘を通して見る画面、検索、検討ログ、週の集計でできます。v1 の機能のあと、答え合わせに、確定している役と近い役を出す「役の欄」を足しました。

## できること

画面の写真と GIF は、試験用のデータで撮っています。雀魂の画面は、プレイヤー名をぼかしたものだけを使っています。検討結果は、プレイヤー名を A〜D に置き換えた固定データです。撮り方は、写真が `scripts/readme-shots.mjs`、GIF が `scripts/readme-gifs.mjs` にあります（どちらも、アプリ自身の窓の中だけを撮ります。[開発](#開発)）。

雀魂の窓の横に置く小さな窓で、常に手前に出ますが、クリックしても雀魂からフォーカスを奪いません。迷ったら、割り当てたボタン（既定はマウスのサイドボタン「戻る」。設定で変えられます）を押すと、その時刻と雀魂の窓のスクリーンショットを保存し（窓が見つからないときは画面全体）、局が終わったら〇△✕でその局の出来を付けます。縦長と横長があり、記録中かどうか、迷いの数、次の評価が何局目かが出ます（「取り消し」で最後の記録を取り消せます）。雀魂が管理者の権限で動いているときは、ボタンを拾う部分だけを、管理者で動く小さな補助プログラム（`jantama-helper.exe`）に分けてあり、設定ページで最初の 1 回だけ Windows の確認を許可すれば、以後は確認なしで起動します。

GIF は、ウィジェットの窓の中のボタンを、撮影の道具が押したものです。この撮影では、記録の命令（迷い・〇△✕・取り消し）を窓の通信の層で受け止めて、本体には通していません。スクリーンショットは、1 枚も撮っていません。

### 半荘の画面

![半荘の画面。見出しに日時と卓と段階とRating、「この半荘を通して見る」のボタン、その下に迷いのカードが並ぶ。カードには、候補と理由を書く欄がある](docs/images/hanchan-cards.png)

![ダークテーマの半荘の画面](docs/images/hanchan-dark.png)

見出しに日時・卓・段階・Rating（Mortal の Rating）が出て、題の下の 1 行に、AI 一致率（自分の判断のうち、AI の 1 位と同じだった割合）・類似度（Mortal の Rating と同じ値）・悪手率（実戦の行動の AI の確率が 5% より低かった判断（悪手）の割合。NAGA の悪手と同じ線）が、説明のアイコンつきで出ます（半荘全体の割合で、判断ごとの AI の答えではありません。迷いだけの設定でも出ます）。その下に迷いのカードが並びます。カードは、スクリーンショット（押すと大きく表示）、局・本場・巡目と迷いの種類、スクリーンショットから読んだ値、結びつけた判断、終局直後のメモの欄（次の節）、「この局面を解く」を持ちます。「推定」のものは「選び直す」や「ほかの候補」で付け替えられます（AI の候補や確率は出しません）。付け直しや選び直しは Ctrl+Z で取り消せ、テーマはサイドバーの下のボタンで、ライトとダークに切り替えられます。

</p>

迷いのカードごとに、「候補」（例: `5p・2m`、`ポン・スルー`）と「理由（1 行）」を書き留められます。AI の答えを見る前に、そのとき考えたことを残すための欄です。局と巡目は聞きません（スクリーンショットの読み取りと結びつけで決まります）。迷いマークを押し忘れた迷いは、カードの並びの下の「迷いマークの無い迷いを足す」で、局と巡目を選んで足せます。書いたメモは、出題・解き直しの答え合わせのあと、「終局直後のメモ」として自分の答えの下に出ます（答える前は出ません）。半荘を通して見る画面の迷いの場面でも、答える前に書けます。

### 局の評価の表と MAKA の当てはめの見込み

![局の評価の表。局ごとの結果、点の増減、自分の〇△✕、AI基準の段階、MAKAの入力、迷いの札が並ぶ。下に、MAKAの評価72局ぶんで合わせた見込みの1行が出ている](docs/images/hanchan-table.png)

半荘の画面の下の「局の評価」の表には、局ごとの結果・点・自分の〇△✕・AI 基準の段階（Mortal の Rating から付けた S+〜E）・MAKA（もう 1 つの検討 AI）の評価（任意で入力）・その局の迷いの札が並びます。札を押すと、その迷いのカードへ移ります。AI 基準と大きく食い違う局には旗が付きます。MAKA の評価を入れるたびに、AI 基準の段階を MAKA に近づける当てはめを合わせ直し、表の下に、いまの見込み（入っている MAKA の評価の局数と、「ぴったり」「±1 段階以内」の割合。1 半荘ずつ外して確かめた値）を出します。

### 局の結果の手

![局の評価の表で、自分が和了した局（東2局1本場）と放銃した局（東3局）の行を開いたところ。局の結果の手（親（対面）の手牌と和了牌、役、飜・符・点数、点の増減と、和了牌を除いた手の待ち）の下に、向聴数の推移の折れ線が出ている。折れ線には、迷い（丸）・悪手（菱形）・聴牌になった打牌（三角）の印が付く](docs/images/hanchan-result.png)

局の評価の表の局の名前（行の頭の矢印つきのボタン）を押すと、その局の結果の手が、行の下に開きます（表の形はそのままで、開かないかぎり増えません）。和了の局は、和了者・ツモかロン（だれから）・手牌（副露と和了牌つき）・役・飜・符・点数・点の増減（本場・供託も）を出します。他家のツモ・ロンの局も同じです。放銃した局は、相手の手牌と、和了牌を除いた手の待ち（待ちの形・残り枚数）も出ます。流局の局は、4 人の手牌を出し、牌山を取り切った流局では聴牌とノーテンを分けます。符の数にマウスを乗せる（キーボードで選ぶ）と、内訳が出ます。その下には、自分の向聴数の推移の折れ線が出ます（自分が切るたびの場面の向聴数。迷いは丸、悪手は菱形、聴牌になった打牌は三角。矢印キーで点を選ぶと内容が出て、「表で見る」で同じ数を表でも読めます）。

Mortal の結果には役・符・点数が入っていないので、牌譜から和了者の手を組み立てて、majiang-core で計算し直しています。固定データの和了 69 件で、役の名前・飜（ドラ・赤ドラ・裏ドラを含む）・符・点数・点の増減（本場・供託を含む）が、結果に付いている牌譜（split_logs）の和了と全部一致することを確かめています。

今日の出題には、迷いを結びつけた局面を先に入れ、足りない分を、AI が実戦の行動に付けた確率が 5% 未満の判断（悪手。NAGA の悪手と同じ線）を、確率の低い順に入れます（1 日に出す数は、設定で変えられます）。2〜3 巡前から盤面を戻して見られます。答えるまで、AI の候補・確率・順位は、画面にも出しません。牌（鳴きの判断はボタン）を選び、理由を 1 行書いて「答え合わせ」を押すと、AI の評価（Mortal）が、実戦と自分の答えに印を付けて出ます。

打牌の判断では、自分・実戦・AI・最大の受け入れ枚数を、向聴数と並べて出します（手牌だけで数えた枚数と、場に見えている牌を除いた残り）。行を押すと、受け入れ牌ごとの枚数と残りが小窓で開きます。打牌のあとが 2 向聴のときは、「2向聴からの先」も出ます。1 向聴に進む牌ごとに、そのあと受け入れが最大になる打牌と枚数を並べ、平均と最大を出します。向聴数が違う打牌どうしは、枚数では比べられないので、「向聴数で差がついた」と出します。そのあと、差の原因（受け入れ枚数・形の質・打点・守備・その他。いくつでも）と、学んだ原則（1 行）を付け、MAKA が推した打牌も任意で入れられます。

### 役の欄

<img src="docs/images/quiz-yaku.png" alt="答え合わせの「役」の欄。ポンとスルーの行動ごとに、確定している役（役牌 東（場風）、1 飜（副露））、近い役、聴牌になる切り方の注が並ぶ" width="336">

答え合わせのあと、受け入れ枚数の欄の下に、欄「役」が出ます（出題・解き直し・半荘を通して見る画面で同じです）。比べる行動（自分・実戦・AI。鳴きの判断はチー・ポン・スルー）ごとに、その行動のあとの手の、確定している役と近い役、役無しの警告を出します。

- 確定している役: どう和了っても付く役。聴牌なら、どの待ちでも付く役です（一部の待ちだけで付く役は「待ち 南 のとき」のように分けます）。立直・門前清自摸和・ドラは数えません。
- 近い役: あと 3 枚以内で、いちばん早い和了より 1 枚遠回りまでで付く役です。役牌・断幺九・混一色（清一色を含む）・一気通貫・三色同順に限り、足りない牌か切る牌を添えます（1 つの行動に 2 行まで）。
- 役無しの警告: 副露して役が無い手は、札「役無し」と太字の文で出します。聴牌しても待ちに役が付かないときは「和了れない」と出します。門前でダマだと役が無い待ちは、薄い注にとどめます。
- 行動の中身が全部同じなら、1 つにまとめて「どの行動でも同じ」と出します。答える前には出ません。

役の判定は、エンジンの自前のコードです（雀魂の規則: 喰いタンあり・後付けあり・赤ドラあり）。正しさは、Python の mahjong と kobalab の majiang-core（MIT）の 2 つの正解表と照らして確かめています（役の欄では、majiang-core は試験だけで使います。次の「待ちと打点」の点数の計算には、実行時にも使います）。

### 待ちと打点・待ちの形・符の内訳

<img src="docs/images/quiz-waits.png" alt="答え合わせのタブ「待ちと打点」。ポンのあとの打牌ごとに、待ち牌の行へ、待ちの形（両面）・どちらでも付く役・ダマのロンとツモの飜・符・点数が並び、符の数に乗せると、副底と明刻の内訳が重なって出ている" width="336">

答え合わせのあと、聴牌になる行動がある場面だけ、既定のタブ「受け入れ・役」のとなりに、タブ「待ちと打点」が出ます（出題・解き直し・半荘を通して見る画面で同じです。聴牌にならない場面には、タブは出ません）。聴牌になる行動は、比べる打牌（自分・実戦・AI）、スルーのままの聴牌、チー・ポンのあとに切る牌、リーチの判断（聴牌になる切り方すべて）です。タブは、← →・Home・End で選べます。答える前には出ません。

- 待ち牌ごとの行: 待ち（牌と、見えている牌と自分の手牌を除いた残り枚数）、待ちの形（両面・嵌張・辺張・双碰・単騎。3 種類以上の待ちは、表の見出しに「多面張」）、どちらでも付く役、ダマとリーチ（門前だけ）それぞれの、ロンとツモの飜・符・点数を並べます。ロンできない待ち（役が無い）は「役なし（ロンできない）」、自分の河にある牌の待ちは「（フリテン）」と出ます。待ちも点も同じ打牌は、1 つの表にまとめます。
- 符は「40符」のように数だけ出し、マウスを乗せる（キーボードで選ぶ）と、内訳（副底・門前ロン・暗刻・明刻・雀頭・待ちなど）が重なって出ます。
- 数えないもの: 裏ドラ・一発・海底などの和了の状況で決まるもの、和了牌が赤のときの赤ドラ（手牌の中の赤は数えます）。点数は、本場・供託を除いた値で、雀魂の規則（切り上げ満貫なし・喰いタンあり・赤ドラ各 1 枚）です。

点数の計算は、kobalab の majiang-core（MIT。版を 1.4.1 に固定し、エンジンの 1 つのファイルの中だけで読み込みます）です。符の内訳は、Python の mahjong の `fu_details` の数え方をエンジンに移したものです（実行時に Python は使いません）。どちらも、Python の mahjong で作った正解表（実戦の聴牌になる全部の待ち・乱数の和了形）と、牌譜の和了 69 件の点の増減（本場・供託を含む）に、全部照らして確かめています。

### 守備の目安

<img src="docs/images/quiz-danger.png" alt="答え合わせのタブ「守備」。対面がリーチしている場面で、切れる牌ごとに、現物・スジ・字牌・無スジの札と短い補足が並び、比べる打牌の行には自分・実戦・AI の印が付いている" width="336">

答え合わせのあと、他家のリーチがある場面と、副露の気配の 1 行を出す他家がいる場面（下の「副露の気配」）だけ、タブ「守備」が出ます（出題・解き直し・半荘を通して見る画面で同じです。どちらも無い場面には、タブは出ません）。切れる牌（打牌とリーチの判断は手牌とツモ牌、鳴きの判断は、チー・ポンのあとに切れる牌）ごとに、リーチした人ごとの分類を 1 語と短い補足で出し、比べる打牌（自分・実戦・AI）の行には印が付きます。リーチした人が 2 人以上のときは、人ごとの欄を、宣言した順に並べます。答える前には出ません。

形式的な分類で、AI（Mortal）の放銃の確率ではありません。リーチした人の河と、場に見えている牌の数だけで、牌を 5 つに分けます。

- 現物: その人の河にある牌と、その人のリーチのあとに通った牌。
- スジ: 両面で待たれる形が、現物のスジで消えている牌（嵌張・辺張・単騎・双碰は残ります）。
- 壁: 両面の形に要る牌が 4 枚見えている牌。
- 字牌: 現物でない字牌（見えている枚数つき）。
- 無スジ: 両面で待たれる形が残っている牌。

リーチしていない他家のうち、副露が多い人と染め手の気配の人には、牌ごとの分類は出さず、気配の 1 行だけを、リーチの人の欄のあとに出します（「副露の気配」。リーチの人がいなくても、この 1 行の人がいれば、タブ「守備」が出ます。その場合は、行と断りだけの欄です）。

- 対象: 副露（チー・ポン・大明槓・加槓。暗槓は数えません）が 2 つ以上の人か、染め手の気配の人（副露が、すべて同じ 1 色の数牌と字牌だけで、その色を含む副露が 1 つ以上あり、河にその色が 1 枚以下）。リーチした人は、対象にしません。
- 行: 「下家: 2副露・索子の染め手の気配・役牌の刻子（發）」のように、副露の数・染め手の色・役牌の刻子（場風・自風・白發中のポン・カン）を書きます（染め手と役牌は、あるときだけ）。

ドラ待ち・巡目は見ていません。分類の順は、固定データのリーチの場面（打牌の判断 133 場面）で、majiang-ai（kobalab。MIT）の危険度の数値の順と照らして、大きく食い違わないことを確かめています（現物の数値は全部 0。分類ごとの平均は、現物 0.00 < 壁 1.07 < 字牌 1.80 < スジ 3.24 < 無スジ 6.64。壁は固定データに 3 件しかなく、実戦では未確認です）。majiang-ai は、試験だけで使う開発用の依存で、アプリには入りません。

### 他家の手牌と、聴牌になった巡目

![通して見る画面で、放銃した局（東3局）の終わりに、他家の手牌を開いたところ。盤面の他家の席に手牌が表向きに並び、対面の河には聴牌になった打牌の枠が付く。右の欄の上に、他家ごとの聴牌の 1 行と向聴数の折れ線、待ち。位置の帯の下に、他家が聴牌になった手の目盛り](docs/images/replay-hands.png)

盤面の他家の席に、手牌が裏向きで並びます（対面は河の上、上家と下家は河の外側。ツモ牌は少し離れます）。どれか 1 人の手牌（河ではありません）を押す（クリック・Enter・Space）と、3 人分が表向きに開き、もう一度押すと閉じます。開いた状態は、手を進めても残り、画面を離れると閉じに戻ります。通して見る画面では、答える場面（迷い・悪手）でなければ、いつでも開けます。答える場面と、出題・解き直しの画面では、答えるまで押せず、表の牌は画面の中にも出しません。

開いているあいだだけ、次のものが出ます（閉じているときは、どれも出ません）。

- 「他家の手牌」の欄（通して見る画面は右の欄の上、答えたあとの場面は答えの欄の上）: 人ごとに、席・風・親・リーチの札、聴牌になった巡目の 1 行（「7巡目に聴牌（3pをチーして 打西・手出し） 待ち 5m・8m」。まだなら「まだ聴牌していません（2向聴）」）、その人が切るたびの向聴数の折れ線（▲ が聴牌になった打牌。矢印キーで点を選ぶと値が出ます）、聴牌している人の待ち（待ちの形・残り枚数・飜・符・点数）。牌の並びは、盤面だけに出ます。
- 河: 聴牌になった打牌に、枠（右上の三角つき）が付きます。
- 位置の帯: 他家が聴牌になった手の目盛りが付き、半荘の中の数と、いまの局の分が、帯の下に書かれます。

「N巡目」は、その人が N 枚目の牌を切ったときです。聴牌になった打牌は、その人の向聴数が 0 でなかった手から 0 になった打牌（鳴いて聴牌になったときは、鳴いたあとの打牌）で、聴牌を崩して、また聴牌になったときは、聴牌の区間ごとの最初の打牌に印が付きます。固定データの 7 半荘（印 110 か所）で、印の位置・経路・待ち・折れ線の点を、別の計算と照らして確かめています。Mortal の結果には他家の手牌は入っていないので、牌譜から、全員の手牌を追い直しています。

## 雀魂の規約について

雀魂の規約に触れないよう、次の線引きを守って作っています。これは作者が引いた線引きで、運営者の承認を受けたものではありません。

- 対局中に、ゲームの画面やデータを機械で読み取りません。スクリーンショットは保存するだけです。画像の文字認識（局・残りの牌・点数の読み取り）は、対局後の取り込みのときにしか行いません。
- ゲームの中でスクリプトや拡張機能を動かしません。ゲームの通信を中継せず、ゲームのプロセスにも触れません。
- 対局中に、画面や情報を外部（人や AI）に送りません。
- 対局中に動くのはウィジェットだけです。ウィジェットは、ユーザーの操作（マウスのボタン、クリック）を受けたときに、画面の保存と記録の追記だけを行います。ボタンを拾う補助プログラムは、入力を本体に知らせるだけで、画面・通信・ファイルは扱いません。
- 牌譜リンクを mjai.ekyu.moe に渡すのは、対局後にユーザー自身が行います。Submit も Cloudflare の確認も、自分で押します。アプリが自動で送ることはありません。
- アプリ自身が行う通信は、mjai.ekyu.moe の結果の JSON の取得だけです。mjai の小さな窓は、サイトを開いて見せるだけで、押すのはユーザーです。

このうち、ゲームのプロセスに触れないこと、雀魂のドメインと通信しないこと、対局中に画面を読まないこと、ウィジェットの操作で外へ送らないことは、ソースの静的検査と単体テスト（`apps/desktop/src-tauri/tests/safety.rs` など）で確かめています。基準は `ACCEPTANCE.md` の「安全」の項にあります。

## 入れ方

GitHub の [Releases](https://github.com/terasaki-8910/JantamaReviewer/releases/latest) から入れます。入れたあとは、起動したときに新しい版を知らせます（「今すぐ入れ直す」で入れ直します。設定の「更新を確かめる」でも確かめられます）。

### Windows

`JantamaReviewer_<版>_x64-setup.exe` を落として動かします。今のユーザーにだけ入れるので、管理者の確認はありません。本体と補助プログラムが同じフォルダに入ります。インストーラーにはコードの署名が無いので、「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押します。

### Mac で使う

1. `JantamaReviewer_<版>_aarch64.dmg` を落として開き、`JantamaReviewer` を「アプリケーション」のフォルダに引きずって入れます。
2. このアプリは Apple の公証を受けていない（ad-hoc の署名だけの）ので、そのまま開くと「壊れているため開けません」と出ます。最初の 1 回だけ、ターミナルで次を実行してから開きます。

   ```sh
   xattr -cr /Applications/JantamaReviewer.app
   ```

3. 開くと検討画面が出ます。Windows の記録を見るには、設定の同期の欄に、Windows で使っている同期先の DB の URL とトークンを入れます（トークンは Mac のキーチェーンに入ります）。
4. アプリ内の更新で入れた版には、`xattr` は要りません。署名が版ごとに変わるので、更新のあと、キーチェーンの確認（同期のトークンを使ってよいか）が出ることがあります。そのときは「常に許可」を押します。

保存先の既定は `~/JantamaReviewerData`、設定のファイルは `~/Library/Application Support/io.github.terasaki-8910.jantama-reviewer/` です。

## 作り方

ソースから作るときに必要なものは、次のとおりです（Mac で作る手順は [analysis/mac/appendix/mac-steps.md](analysis/mac/appendix/mac-steps.md) の A にあります）。

- Node.js（動作確認は v25.2.1）と pnpm 11（`packageManager` は `pnpm@11.9.0`）
- Rust 1.90 以上（Windows では MSVC のツールチェーン。Visual Studio の C++ ビルドツールが要ります）
- Microsoft Edge WebView2 ランタイム

```powershell
git clone https://github.com/terasaki-8910/JantamaReviewer.git
cd JantamaReviewer
pnpm install
pnpm --filter @jantama/desktop tauri build --no-bundle
```

`apps\desktop\src-tauri\target\release\` に、本体の `jantama-reviewer.exe` と、管理者の補助プログラムの `jantama-helper.exe` ができます。2 つは同じフォルダに置いておきます。`jantama-reviewer.exe` を起動すると、ウィジェットが出ます。検討画面は、ウィジェットを右クリックして「検討画面を開く」か、タスクトレイのアイコンから開きます。

雀魂が管理者の権限で動いていると、その窓が前面にある間、普通の権限のアプリにはマウスのボタンが届きません。その場合は、設定ページの「管理者の補助プログラムを設定する」を押して、Windows の確認で「はい」を選びます。最初の 1 回だけです。補助プログラムは Program Files に写され、確認なしで起動するタスクが登録されます。「設定を解除する」を押すと、その写しとタスクが消えます。補助プログラムを設定していなくても、管理者ではない窓の上なら、本体だけで動きます。

## 使い方

1. 対局中: 迷ったら、割り当てたボタンを押します。局が終わったら、ウィジェットで〇△✕を付けます。
2. 対局のあと: 雀魂で牌譜を共有（コピー）して、アプリの窓に戻ります。「この半荘を取り込みますか」で「取り込む」を押し、「mjai で検討する」で開く小さな窓で Submit を押します。mjai の設定は、サイトの既定のまま（Mortal 4.1b balanced・温度は既定）にします。毎回同じ設定にすると、結果を比べられます。
3. 取り込みが終わったら、半荘の画面を開きます。迷いのカードの結びつけを確かめ（違っていたら選び直します）、迷いごとに、候補と理由のメモを書き留めます（押し忘れた迷いは「迷いマークの無い迷いを足す」で足します）。局の評価の表で、自分の〇△✕と AI 基準を見比べ、必要なら MAKA の評価を入れます。
4. 毎日: サイドバーの「今日の出題」を開いて、AI の答えを見る前に、自分の答えと理由を書きます。答え合わせのあと、差の原因と学んだ原則を付けます。期限の来た問題は、「解き直し」に出ます。
5. 見直したいとき: 「この半荘を通して見る」で半荘を通して見て、迷いと悪手の場面へ飛びます。「ログ」で答えた問題を絞り込み、Ctrl+K の検索で、半荘や問題を探します。週に 1 回、「週の集計」で、差の原因・局面の種類・自己評価のずれを見て、成績と来週の重点を書きます。
6. 記録を残すとき・写すとき: 設定ページの「記録の書き出し」で、記録だけの JSON を書き出します。

データは、半荘ごとのフォルダに保存します（既定は `%USERPROFILE%\JantamaReviewerData\games\<開始時刻>\`）。ウィジェットの記録（`events.jsonl`。追記式）、迷いと評価のスクリーンショット（`marks\`・`ratings\`）、取り込んだ結果（`report.json`）、文字認識の写し（`ocr.json`）、結びつけ（`links.json`）、自分の評価の付け直し（`self-ratings.json`）、MAKA の評価（`maka.json`）、終局直後のメモ（`memos.json`）、解決した局面（`resolved.json`）、NAGA の結果の URL（`naga.json`）が入ります。答え・解き直しの予定・今日の出題・週の成績は、保存先の直下の `study.sqlite` に入ります。保存先は、Git のリポジトリの外に限ります。

## 開発

構成は、Tauri v2 のデスクトップアプリ（`apps/desktop`。画面は React と TypeScript、`apps/desktop/src-tauri` は Rust の本体・`input`・`helper`・`ocr`）と、牌譜の再生や評価の計算を受け持つ TypeScript の `packages/engine` です。

```powershell
pnpm install          # 依存の取得
pnpm test             # 全 vitest と cargo test --workspace
pnpm lint             # eslint・stylelint・tsc・cargo clippy・cargo fmt
pnpm dev              # tauri dev（先に pnpm build:helper で補助プログラムを作っておく）
pnpm build:debug      # デバッグビルド（本体と補助プログラム）
```

- 守備の目安の試験（`packages/engine/tests/danger.test.ts`）は、majiang-ai の危険度の数値（`devDependencies`。配らない）と、分類の順を照らします。
- 待ちと打点の正解表（`packages/engine/tests/fixtures/win-value-oracle.json`）は、`packages/engine` で `WIN_VALUE_DUMP=1 pnpm exec vitest run tests/win-value-dump.test.ts` を動かしたあと、`tests/fixtures` で `uv run --offline --with mahjong python generate_win_value.py` を動かすと、作り直せます。
- 実機の入力を通す手動の試験は、`pnpm test:hook`（本物のフックに入力を注入）と `pnpm test:task`（本物のタスクスケジューラ）です。`pnpm test` には含めていません。
- 試しに動かすときは、環境変数 `JANTAMA_CONFIG_DIR` に一時フォルダを指定し、そこの `settings.json` の `data_dir` も一時フォルダにします。本物のデータには触れません。
- README の画面写真は、`node scripts/readme-shots.mjs <迷いマークの画像のフォルダ>` で、作った実行ファイルから撮り直せます（一時フォルダだけを使います）。GIF は、`node scripts/readme-gifs.mjs <迷いマークの画像のフォルダ>` で録り直せます（ffmpeg が PATH に要ります）。どちらも、アプリ自身の窓を WebView2 の遠隔デバッグ（CDP）で操作して撮るので、画面全体やほかのアプリは撮りません。ウィジェットの GIF では、迷い・〇△✕・取り消しの命令を窓の通信の層で受け止め、本体には通しません。
- 仕様は [SPEC.md](SPEC.md)、受け入れ基準は [ACCEPTANCE.md](ACCEPTANCE.md)、決めたことの記録は [docs/decisions.md](docs/decisions.md) にあります。コード内のコメント・文書・コミットメッセージは日本語で、識別子だけ英語です。
