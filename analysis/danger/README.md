# 危険度の推定・手牌の安全度の見える化・自前の検討の調べ

決定記録「2026-10-30 チャットでの依頼（危険牌の予測・安全度の見える化・自前のモデルでの検討・Hugging Face の調べ）」を受けた、作る前の調べ。2026-10-30、Claude。
製品のコード・SPEC・ACCEPTANCE は変えていない。作るかどうか・どの形にするかは、ユーザーに案を見せてから決める。

根拠の印: [試した] この PC で実際に動かした結果。[出典 n] 末尾の一覧。[推測] 確かめていない見込み。[別セッション] 麻雀 AI を作っているセッション（mahjongai-d9、リポジトリ MahjongAI）の回答。

## 1. 結論

- 決まりごとの数え上げ（現物・スジ・壁。今の「守備の目安」）の先は、学習した「読み」（他家ごとの聴牌の確率と、34 種の待ちの確率）。公開の既製品 `hhim8826/mortal3-b40c192` の `tenpai.onnx` が、この PC で動き、ユーザーの半荘で、決まりごとでは同じ「無スジ」になる牌に 5%〜21% の差を付けた [試した]。
- 理由づけは、(1) 数の分解（他家ごとの聴牌率・この牌の当たりの率・今の印）と、(2) 効いた捨て牌（その捨て牌が無かったらの読み直し。モデルに忠実で、作り話が混ざらない）を軸にする [試した]。表の形のモデルなら (3) 要因の寄与（SHAP）も出せる [出典 19]。LLM は、計算した事実の言い換えにだけ使う [出典 2, 15][別セッション]。
- 自前の検討（mjai.ekyu.moe に頼らない解析）: 牌譜は今のまま mjai のサイトから取る（取り込んだ report.json の `mjai_log` に全員の配牌まで入っている [試した]）。雀魂の牌譜は、ログインした状態でしか取り出せず、取り出す道具はゲームの中で拡張機能を動かす形なので、2章の線引きでは使えない [出典 25]。解析だけを手元のモデルで行う。
- Mortal 系のモデルは、libriichi（AGPL-3.0）の観測の組み立てが要る。本体（MIT）に組み込むと本体が AGPL の義務を負うので、AGPL の別のプログラム（解析エンジン）にして本体から呼ぶのが現実的 [別セッション]。
- Hugging Face に、雀魂の段位戦の pt を狙って学習し、強さの根拠があるモデルは無い。トップ寄りは `haor/Mortal-S42`（Apache-2.0）、ラス回避寄りは Akagi の配る v4（Hugging Face に無く、出どころとライセンスが不明）。

## 2. 試した結果（ユーザーの 2026-10-22 23:25 の半荘、席 2）

手順: report.json の写しを一時フォルダに置き、別セッションの WSL の libriichi（読むだけ）で、本人の席から見た v3 の観測（934×34）を、他家がリーチしている間の自分のツモごとに作った（17 局面）。それを `tenpai.onnx`（sha256 50893ddc…）に onnxruntime（CPU）でかけた。実際の待ちは、牌譜の全員の手牌から数えた。

ほかの局面では、上位の読みに実際の待ちが入らないこともあった（例: 東2局2本場、待ち 2p・5p・8p に対し、上位は 3p・2p・6m）。読みは確率で、外れもある。1 半荘の 17 局面の推論は 1 秒未満、反実仮想は 1 局面あたり約 10 回の読み直し [試した]。

モデルの作り手の測定（天鳳の鳳凰卓、取り分けた 418 万組）: リーチに対する無スジの牌の中で、決まりごと（リーチ・現物・スジ・巡目）は安全な 1 割と危険な 1 割を 6.2% と 9.0% にしか分けられないが、このモデルは 0.13% と 17.2% に分ける。副露した手に対しては 0.01% と 8.4%（決まりごとは 0.02% と 4.0%）。13% と出した牌が 12.7%、23% と出した牌が 20.7% の割合で実際に待ち牌で、30% を超えると少し言い過ぎ。聴牌の Brier 0.0427（基準率 0.147）[出典 26]。
注意: 学習のラベルは「待っている」で、「ロンできる」（役・フリテン）ではない [出典 26]。

ほかのツールの見せ方: mahjong-helper（MIT）は牌ごとの危険度を、現物・5% 未満・5〜10%・10〜15%・15% 超の段で色分けする [出典 10]。NAGA の解析の JSON には、他家ごとの聴牌の度合い（tenpai）と、聴牌の度合い×待ちの予測の合成（danger）がある [出典 6]。Mortal は他家の危険度を出さない [出典 4]。

## 5. ライセンスと規約（ユーザーの判断が要るところ）

- Mortal と libriichi は AGPL-3.0。本体に組み込むと、本体を AGPL で配る義務が出る。別のプログラムとして呼ぶなら、本体は MIT のまま（別のプログラムのソースは公開する）[別セッション]。法的な判断ではない。
- 天鳳の牌譜の規約（tenhou.net/man/）は、天鳳で打つことを前提としないサービスでの利用、競合する物での利用などを禁じ、ほかの用途は許可を求めている [出典 1]。天鳳の牌譜で学習したモデル（Mortal 系のすべて。mjai.ekyu.moe の公式の Mortal も含む）を使うことの扱いは、はっきりしない。自前で学習するなら、S42 の自己対局（別セッションで 1 時間に約 3 万局）とユーザー自身の半荘を使えば、この問題を避けられる（自己対局の相手は S42 なので、人の打ち方とのずれがあり、ユーザーの半荘で較正し直す）。
- Hugging Face からモデルを取るなら、外への通信の先（S-2）に huggingface.co を足すことになる。足さないなら、ユーザーが自分で落としたファイルを選ぶ形にする。
