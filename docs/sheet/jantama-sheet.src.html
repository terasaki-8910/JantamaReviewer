安全のために確かめていること

アプリが外へ出す通信は、mjai の結果の JSON を取る1か所だけです（https だけ、転送先には移らない、大きさの上限つき）。mjai の窓からは、アプリの機能を呼べません。窓で開けるのは mjai のサイトと Cloudflare の確認だけです。文字の読み取りは取り込みの1か所からしか使えず、ウィジェットとボタンを拾う部分には入っていません。どれもテストで毎回確かめています。

聞かずに決めたこと（9回目）

違うと思うものがあれば、番号を最後の自由記入に書いてください。

  1. 評価のスクショに写った局が始まったばかり（残り66枚以上）なら、その前の局の評価とみなす（終わった局を、次の局が始まってから付けたため）。局の途中ならその局。読めないものは押した順で当てはめる。
  2. 段階の当てはめのいまのデータ（MAKA の評価67局）に D と E が無いので、Rating がとても低くても C- までしか出ない。MAKA の評価を入れていくと当てはめ直す（当てはめ直しと「ぴったり何割」の表示は、ログ・集計と一緒に作る）。
  3. ごみ箱が使えない場所（ネットワークのドライブ、ごみ箱を切っている設定など）では、消した半荘はアプリを閉じたときにそのまま消える（エクスプローラーと同じ。確認は出さない）。
  4. 試しに動かすときは、画面の保存領域（WebView2）も一時フォルダに分ける。mjai の窓の保存領域は、いつもアプリの画面とは別にする（外のサイトの保存領域を混ぜない）。
  5. クリップボードは、検討画面が前面に来たときに文字だけ読む（長すぎる文字は読まない、保存しない）。2か所から同時に読むと本体が落ちる不具合が見つかったので、同時に読まない形に直した。
  6. 出題の画面では、答える前に「実戦：打3m」のように実戦の行動を見せる（2回目の見本のとおり）。解き直しでは見せない。
  7. 出題の盤面では、鳴かれた牌も河に薄く残す（雀魂では河から消えるが、何が鳴かれたかを見やすくするため）。
  8. 迷いに結びついた局面の自分の行動に「東をポン」のように書くのは、実戦であなたがした行動だけ。AI の行動は出題の答え合わせまで出さない。
